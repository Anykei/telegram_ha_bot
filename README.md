# Home Assistant Telegram Bot

Telegram HA Bot - это Telegram-бот для управления Home Assistant из чата. Он
показывает комнаты и устройства, обновляет открытые экраны, отправляет
уведомления, строит графики датчиков, работает с камерами и ограничивает доступ
разным пользователям.

Проект рассчитан на сценарий, где Home Assistant и камеры доступны боту в
локальной сети, а пользователь управляет домом через Telegram из любой точки.

## Возможности

- Управление устройствами Home Assistant по комнатам.
- Экраны для света, сенсоров, климата, числовых сущностей и настроек.
- Персональные профили доступа: `user`, `child`, `guest`.
- Скрытие комнат и устройств или перевод устройств в режим просмотра.
- Уведомления по изменениям состояний HA с учетом прав пользователя.
- Графики истории датчиков.
- Двуязычный интерфейс: `ru` и `en`.
- Текстовые команды: например `свет коридор вкл`, `снимок вход`,
  `архив камера 3`.
- Голосовые команды через Home Assistant Assist STT pipeline.
- Персональный voice engine для пользователя: локальный парсер, HA readonly или
  HA full.
- Раздел камер без внешнего HTTPS-сервера: снимок, короткое видео, архив.
- Событийная запись камер по правилам Home Assistant.
- Группы правил записи: например `Охрана`, `Тест`, `Ночь`, `Двери`.
- Health-экран камер: последняя проверка, размер файла, последняя ошибка.
- Журнал активности для действий, камер, записей и ошибок.
- Фон интерфейса из кадра выбранной камеры.
- Защита UI от отката при фоновых обновлениях и Telegram rate limit.
- Восстановление активных UI-сессий после перезапуска.
- Синхронизация имен устройств из HA без затирания ручных alias.

## Архитектура

Бот синхронизируется с Home Assistant через REST API и WebSocket events. Данные
о комнатах, устройствах, пользователях, правах, камерах, правилах записи и
сессиях хранятся в SQLite.

Основные части:

- `src/bot` - Telegram handlers, router, экраны, форматирование и текстовые
  команды.
- `src/core` - фоновые worker, уведомления, камеры, запись, presentation layer.
- `src/db` - SQLite-репозитории и правила доступа.
- `src/ha` - клиент Home Assistant и WebSocket listener.
- `migrations` - схема базы данных.
- `data/options.json` - локальная конфигурация бота, обычно не коммитится.

## Требования

- Rust 1.87+.
- SQLite.
- Home Assistant с long-lived access token или Supervisor token.
- Telegram bot token от BotFather.
- Для камер: доступный для бота RTSP/HTTP-поток.
- Для сборки с камерами: системные библиотеки FFmpeg/LibAV.

Debian/Ubuntu:

```bash
sudo apt-get update
sudo apt-get install -y \
  pkg-config clang libclang-dev libssl-dev libsqlite3-dev \
  libfreetype6-dev libfontconfig1-dev \
  libavformat-dev libavcodec-dev libavutil-dev libavfilter-dev \
  libavdevice-dev libpostproc-dev libswscale-dev libswresample-dev
```

macOS:

```bash
brew install ffmpeg pkg-config sqlite openssl
```

## Конфигурация

Бот читает пути и Home Assistant из переменных окружения:

```env
OPTIONS_PATH=data/options.json
DATABASE_PATH=data/bot_data.db
MIGRATIONS_PATH=./migrations

HA_URL=http://homeassistant.local:8123
HA_TOKEN=your_home_assistant_long_lived_token

RUST_LOG=info
```

В Home Assistant Add-on окружении вместо `HA_TOKEN` может использоваться
`SUPERVISOR_TOKEN`, а `HA_URL` по умолчанию равен `http://supervisor/core`.

Минимальный `options.json`:

```json
{
  "bot_token": "123456:telegram_bot_token",
  "root_user": "123456789"
}
```

Расширенный пример:

```json
{
  "bot_token": "123456:telegram_bot_token",
  "root_user": "123456789",
  "background_maintenance_interval_s": 15,
  "event_refresh_min_interval_s": 5,
  "session_ttl_hours": 24,
  "telegram_retry_after_extra_delay_s": 1,
  "default_language": "ru",
  "camera_clip_intervals_s": [5, 10, 15, 30],
  "camera_default_clip_s": 10,
  "camera_recording_max_tail_seconds": 300,
  "camera_recording_max_segment_seconds": 300,
  "camera_recording_max_parallel_jobs": 4,
  "camera_recording_storage_root": "data/recordings",
  "voice_enabled": false,
  "voice_stt_provider": "ha_pipeline",
  "voice_command_engine": "local_parser",
  "voice_ha_pipeline_id": null,
  "voice_stt_sample_rate": 16000,
  "voice_confirm_dangerous": true,
  "voice_pending_ttl_s": 60,
  "voice_max_audio_size_mb": 10,
  "voice_max_audio_duration_s": 30,
  "voice_stt_timeout_s": 45,
  "voice_show_recognized_text": true,
  "voice_response_format": "text"
}
```

Почти все поля, кроме `bot_token` и `root_user`, имеют значения по умолчанию.

`default_language` поддерживает `ru` и `en`. Персональный язык меняется в
админке: пользователи -> профиль -> язык.

`voice_command_engine` в `options.json` задает режим по умолчанию. В профиле
пользователя его можно переключить отдельно: `local_parser`,
`ha_conversation_readonly`, `ha_conversation_full`. Команды камер бота
(`снимок`, `видео`, `архив`) всегда обрабатываются ботом, даже если пользователю
выдан полный HA Conversation.

`local_parser` - самый безопасный режим: бот сам разбирает команду, проверяет
права Telegram-профиля и вызывает HA service. `ha_conversation_readonly`
разрешает вопросы к HA Assist без управления устройствами. `ha_conversation_full`
делегирует нераспознанные ботом команды в HA Conversation, поэтому его стоит
выдавать только доверенным пользователям.

`voice_response_format` уже хранится в настройках для будущего TTS-ответа, но
текущая реализация отправляет результат текстом.

Камеры в `options.json` не добавляются. Они создаются через Telegram-админку и
хранятся в SQLite.

## Запуск локально

```bash
cargo run
```

При первом запуске применяются миграции из `MIGRATIONS_PATH`, создается или
обновляется SQLite-база, затем бот подключается к Home Assistant.

Проверка перед запуском:

```bash
cargo fmt --check
cargo check --locked
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

## Запуск в Docker

Сборка:

```bash
docker build -t telegram-ha-bot .
```

Пример запуска:

```bash
docker run --rm \
  --name telegram-ha-bot \
  -e OPTIONS_PATH=/data/options.json \
  -e DATABASE_PATH=/data/bot_data.db \
  -e MIGRATIONS_PATH=/app/migrations \
  -e HA_URL=http://homeassistant.local:8123 \
  -e HA_TOKEN=your_home_assistant_token \
  -e RUST_LOG=info \
  -v "$PWD/data:/data" \
  telegram-ha-bot
```

Если контейнер не резолвит `homeassistant.local`, укажите IP Home Assistant,
настройте DNS или используйте подходящий Docker network mode.

## Первый запуск

1. Создайте Telegram-бота через BotFather.
2. Укажите `bot_token` и `root_user` в `options.json`.
3. Укажите `HA_URL` и `HA_TOKEN` в `.env` или окружении контейнера.
4. Запустите бота.
5. Напишите боту `/start` от пользователя `root_user`.
6. В админке добавьте остальных пользователей.

`root_user` всегда имеет полный доступ и видит админку.

## Профили доступа

Профили нужны, чтобы разные люди видели разные части дома:

- взрослый пользователь видит все комнаты и устройства;
- ребенок не видит котел или серверную;
- гость видит только свет в гостиной.

Режимы доступа:

- `полный` - видно и можно управлять;
- `просмотр` - видно, но управление запрещено;
- `скрыто` - не видно в меню и недоступно по callback.

Роли переключаются по кругу:

```text
user -> child -> guest -> user
```

Для `child` и `guest` комнаты по умолчанию закрываются, после чего админ
открывает нужные комнаты и устройства вручную.

## Камеры

Раздел камер работает без Telegram Mini App и без внешнего HTTPS-сервера. Бот
получает кадр или короткий клип сам и отправляет его в чат как фото или видео.

Пользователь видит только камеры тех комнат, к которым у него есть доступ.

Админский путь добавления:

```text
Админка -> Камеры -> выбрать комнату -> Добавить камеру
```

Формат ввода:

```text
Название
RTSP URL
Интервал видео в секундах
Snapshot URL необязательно
```

Пример:

```text
Вход
rtsp://user:password@192.168.1.50:554/stream1
10
http://192.168.1.50/snapshot.jpg
```

Можно вводить одной строкой через `;`:

```text
Вход; rtsp://user:password@192.168.1.50:554/stream1; 10; http://192.168.1.50/snapshot.jpg
```

Если `Snapshot URL` не указан, бот попробует взять кадр из видеопотока. Если
камера или go2rtc умеет отдавать JPEG snapshot, лучше указать отдельный
snapshot URL: это быстрее и стабильнее.

### go2rtc

Если камера заведена в go2rtc, можно добавить поток так:

```text
USB камера
rtsp://homeassistant.local:8554/usb_camera
10
http://homeassistant.local:1984/api/frame.jpeg?src=usb_camera
```

Для коротких MP4-клипов желательно, чтобы поток уже был H.264. Для MJPEG/USB
камер удобнее делать H.264 в go2rtc и отдавать боту RTSP-поток go2rtc.

## Событийная запись камер

Бот умеет запускать запись камеры по событиям Home Assistant. Правила хранятся
в SQLite и настраиваются в Telegram-админке.

Пример сценария:

```text
Дверь открылась -> записать камеру "Коридор" 60 секунд -> хранить 30 дней
```

Особенности:

- запись не блокирует Telegram UI;
- повторное событие по той же камере продлевает активную запись;
- если одна камера привязана к нескольким событиям, создается одна активная
  сессия записи, а не несколько конкурирующих worker;
- длинная запись режется на сегменты до `max_segment_seconds`;
- готовые сегменты доступны в архиве конкретной камеры;
- при отправке в Telegram видео сжимается во временный файл;
- временные файлы после отправки удаляются;
- отправленные части можно автоматически удалить из чата через минуту;
- старые записи очищаются по `retention_days`;
- готовая запись отправляет уведомление `root_user` и подписчикам датчика.

Путь:

```text
Админка -> Камеры -> выбрать комнату -> Правила записи
```

Текстовый формат правила:

```text
Название правила
camera_id
any
entity_id;operator;from_state;to_state;value
tail_seconds
max_segment_seconds
cooldown_seconds
retention_days
```

Пример для света в коридоре:

```text
Тест: свет в коридоре
3
any
switch.vykliuchatel_0;changed_from_to;off;on;
switch.vykliuchatel_0;changed_from_to;on;off;
60
30
0
30
```

Поддерживаемые операторы условий:

- `changed_to`
- `changed_from_to`
- `is`
- `is_not`
- `contains`
- `above`
- `below`

Логика условий:

- `any` - достаточно одного совпавшего условия;
- `all` - событие должно совпасть хотя бы с одним условием, а остальные условия
  должны быть истинны по текущему состоянию HA.

Группы правил позволяют включать и выключать наборы правил целиком. Например,
можно держать тестовые правила выключенными, а группу `Охрана` включать только
на ночь или при уходе из дома.

## Текстовые команды

Текстовые команды работают как быстрый слой поверх обычного UI. Они учитывают
доступы пользователя. Команды перехватываются только когда пользователь не
находится в активном диалоге ввода, поэтому они не мешают добавлению камер,
правил и алиасов.

Примеры:

```text
свет коридор вкл
свет коридор выкл
снимок вход
видео камера 3 10
архив камера 3
включи на кухне люстру и подсветку
включи свет во всех комнатах
```

Поиск устройств учитывает имя, alias, `entity_id`, комнату и слова в любом
порядке. Если найдено несколько подходящих устройств или камер, бот попросит
уточнить запрос.

Массовые действия и команды на несколько устройств требуют подтверждения. Если
Home Assistant вернул ошибку при выполнении service call, бот показывает ошибку
и не сообщает ложный успех.

## Голосовые команды

В режиме `local_parser` голосовое управление использует безопасный путь:

```text
Telegram voice -> HA Assist STT -> текст -> command engine бота -> проверка прав -> HA service call
```

Home Assistant Assist запускается только до стадии `stt`, поэтому в локальном
режиме команды не выполняются в HA до проверки Telegram-профиля. Для
пользователя дополнительно есть право `can_use_voice`, а устройства с флагом
`critical` требуют подтверждения кнопкой. Pending confirmations хранятся в
SQLite и выполняются только после успешного подтверждения; если HA call упал,
подтверждение не теряется до истечения TTL.

В MVP голосовые команды поддерживают тот же набор действий, что и текстовые
команды: управление устройствами, снимок камеры, короткое видео и архив камеры.

Поддерживаемые режимы:

- `local_parser` - команды выполняет бот после проверки профиля.
- `ha_conversation_readonly` - бот разрешает read-only вопросы к HA Conversation.
- `ha_conversation_full` - бот сначала обрабатывает свои команды камер, а
  остальные отправляет в HA Conversation. Этот режим подходит только доверенным
  пользователям.

## Админка

Админка доступна только `root_user`.

Основные разделы:

- пользователи и профили доступа;
- комнаты и устройства;
- камеры по комнатам;
- правила записи камер;
- группы правил;
- health камер;
- журнал активности;
- настройки фоновой картинки UI;
- статус системы;
- backup SQLite-базы.

Экран статуса показывает:

- состояние Home Assistant;
- последний heartbeat фоновых worker;
- результат последней синхронизации HA;
- число пользователей, комнат, устройств, подписок и событий;
- активные UI-сессии;
- активные записи камер;
- паузы live refresh после Telegram rate limit.

### Синхронизация Home Assistant

Комнаты и устройства синхронизируются из HA через Template API. Бот использует
`area_id(entity_id)`, поэтому может подтягивать сущности, привязанные к комнате
на уровне HA device/entity registry. Имя из HA хранится отдельно как `ha_name`,
а ручной alias пользователя не затирается.

Если HA sync прошел частично с ошибками, бот не архивирует "пропавшие"
устройства в этом цикле, чтобы временный сбой Template API не скрыл живые
устройства из интерфейса.

## Уведомления и графики

Бот слушает события Home Assistant через WebSocket. При изменении состояния он
может отправлять уведомления подписанным пользователям, но учитывает доступы:
если устройство скрыто или уведомления отключены для пользователя, событие не
будет отправлено.

Для датчиков доступен просмотр истории и графики. В Docker-образ добавлены
шрифты и библиотеки, нужные для генерации изображений графиков.

## CI/CD и релизы

CI запускает:

```bash
cargo fmt --check
cargo check --locked
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

Release workflow собирает Docker image для `linux/amd64` и `linux/arm64`,
публикует его в GHCR и обновляет Home Assistant add-on store.

Версия релиза определяется Git-тегами через conventional commits:

- `fix:` -> patch, например `0.1.0` -> `0.1.1`;
- `feat:` -> minor, например `0.1.0` -> `0.2.0`;
- `BREAKING CHANGE:` или `feat!:` -> major, например `0.1.0` -> `1.0.0`.

Если явного типа в коммитах нет, используется `default_bump: patch`.

## Безопасность

- Не коммитьте `.env`, `data/options.json`, SQLite-базу и файлы записей.
- Если токен Telegram или Home Assistant попал в чат, логи или репозиторий,
  перевыпустите его.
- `root_user` должен быть Telegram user id, не username.
- Камеры могут содержать логин и пароль прямо в RTSP URL. Относитесь к базе,
  backup-файлам и архиву записей как к секретам.

## Отладка

Включите подробные логи:

```env
RUST_LOG=info
```

Частые проблемы:

- `HA_TOKEN not set` - не задан `HA_TOKEN` или `SUPERVISOR_TOKEN`.
- `homeassistant.local` не открывается из Docker - используйте IP адрес,
  настройте DNS или сетевой режим контейнера.
- Камера не отдает клип - проверьте, что RTSP URL доступен именно с машины или
  контейнера, где запущен бот.
- Клип не воспроизводится в Telegram - попробуйте H.264 поток через go2rtc.
- Снимок с камеры медленный - добавьте отдельный `Snapshot URL`.
- Telegram временно ограничивает редактирование сообщений - бот ставит live
  refresh на паузу и показывает это в статусе системы.
- Видео слишком большое для Telegram - уменьшите длительность сегмента или
  используйте поток с меньшим битрейтом.
- Устройство видно в HA, но не в боте - проверьте, что entity/device назначен в
  HA Area, и посмотрите статус последней синхронизации HA в админке. Если имя
  задано только в Lovelace-карточке, HA API может не отдавать его как имя
  сущности.
