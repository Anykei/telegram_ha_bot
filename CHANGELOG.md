# Changelog

Все заметные изменения проекта фиксируются в этом файле.

Формат близок к Keep a Changelog, версии следуют Semantic Versioning. Релизный
workflow вычисляет следующую версию по conventional commits:

- `fix:` -> patch;
- `feat:` -> minor;
- `BREAKING CHANGE:` или `feat!:` -> major.

## [Unreleased]

### Added

- Добавлен HTML-интерфейс внутри чата Telegram: главное меню, комнаты,
  устройства, сценарии, камеры, архив, настройки, администрирование и справка
  на русском и английском. Переключение между HTML и обычным интерфейсом
  сохраняется для пользователя; отдельный сайт для управления не требуется.
- Графики в HTML поддерживают выбор периода через календарь с часами и
  минутами, а также отправку полноценного PNG отдельным сообщением.
- Добавлена настройка камеры для сохранения вручную запрошенных видео
  в архив; по умолчанию она выключена. Во время подготовки видео кнопка
  заблокирована и показывает ожидание.
- Добавлены изолированный мок Home Assistant и проверка HTML-экранов
  с реальным HA без отправки команд устройствам.
- Подготовлен `CHANGELOG.md` для ведения истории релизов.
- Добавлен флаг критичного устройства в настройки устройства.
- Добавлен MVP голосовых команд через HA Assist STT pipeline.
- Добавлено право пользователя `can_use_voice`.
- Добавлены SQLite pending confirmations для критичных команд.
- Добавлен персональный `voice_command_engine` для пользователей:
  `local_parser`, `ha_conversation_readonly`, `ha_conversation_full`.
- Добавлена обработка read-only и full запросов через HA Conversation API.
- Добавлены голосовые и текстовые массовые команды для света и групп устройств,
  включая команды вида `включи на кухне люстру и подсветку`.
- Добавлено отдельное поле `devices.ha_name` для имени, синхронизированного из
  Home Assistant.
- Добавлен мастер создания правил записи для `binary_sensor`, `sensor`,
  `number`, `switch` и `light`.

### Changed

- Уведомления и отправленные пользователю видео удаляются по настройке
  `delete_notification_messages_timeout_s`; значение `0` отключает удаление.
  Удаление сообщения с видео не удаляет запись из архива.
- В HTML-режиме изменения состояния устройств показываются на главном
  экране и странице статусов без дублирующих сообщений в чате.
- HTML-карточки используют общий layout: компактное обновление справа
  вверху, навигация внизу, строки управления не выше двух строк текста.
  Состояние ожидания команды сохраняется при навигации; повторные нажатия
  не запускают ту же операцию повторно.
- Зависимости обновлены; минимальная версия Rust — 1.99, релизная — 1.99.1.
  Для `proc-macro-error2` временно включено локальное исправление совместимости.
- CI веток проверяет Rust, виджеты и workflow; Docker собирается только
  релизным workflow из `main`. Релиз рассчитывает версию
  по коммитам, подставляет её в бинарник и согласованно обновляет образы двух
  архитектур, Git-тег и магазин аддонов; повторный запуск использует ту же версию.
- Карточки камер показывают время получения кадра и предупреждают об устаревшем
  изображении или ошибке обновления; время обновления меню подписано отдельно.
- Синхронизация HA теперь использует `area_id(entity_id)` и имена из
  `device_attr(..., 'name_by_user'/'name')`, чтобы лучше подтягивать устройства,
  привязанные к комнате на уровне HA registry.
- Пример создания правила записи в админке теперь покрывает оба перехода двери:
  открытие и закрытие.
- При запуске бот логирует версию и безопасные runtime-параметры без токенов.
- HA-шаблон синхронизации комнат теперь выводит строки через `to_json`, чтобы
  имена с кавычками, обратными слешами и переносами не ломали JSON.
- Текстовые команды перехватываются только в `State::Idle`, не мешая активным
  диалогам добавления камер, правил и алиасов.
- Sync устройств больше не затирает ручной alias пользователя именем из HA.
  HA-имя хранится отдельно в `ha_name`.
- Pending confirmations теперь помечаются выполненными только после успешного
  выполнения команды.

### Fixed

- Устранено предупреждение FFmpeg `deprecated pixel format` при обработке
  кадров YUVJ: диапазон цвета теперь задаётся явно до инициализации конвертера.
- Исправлен разбор обновлений Telegram для HTML-виджетов и обычных сообщений.
- В HTML восстановлены переходы к термостату и настройкам камеры, возврат
  в главное меню при устаревшей сессии, полнота меню и отображение длинных
  страниц журнала и статуса системы. Добавлена тематическая справка.
- Списки камер, режимов записи, групп действий и сцен HA разбиты на страницы
  по 10 элементов. Возврат восстанавливает позицию; административные кнопки
  создания, удаления и настройки остаются доступны. Порядок при совпадении
  имён стабилизирован по ID.
- Текстовые экраны длиннее лимита Telegram доступны по страницам вместо
  обрезки. Сохраняются фильтры, кнопки возврата, обновление и состояние ввода.
  Каждая страница загружает актуальные данные и повторно проверяет доступ;
  маршрут и результат команды хранятся в SQLite с привязкой к пользователю,
  без копии состояния устройств. Длинный результат можно дочитать после
  выполнения без повторной отправки команды. Старые команды перед загрузкой
  заменяются просмотром состояния.
- Статус, запись камер, предупреждения и время актуальности сохраняются на
  текстовых страницах; особенно большие блоки статуса тоже доступны целиком
  по страницам. Фоновое обновление не сбрасывает читаемую страницу.
- Лимиты Telegram проверяются по отображаемому тексту с учётом Unicode.
  Экранирование Markdown больше не переводит короткое меню в текстовый режим;
  после длинного экрана возвращается настроенный фон, включая кадр камеры.
- Добавлены проверки полноты длинного журнала, сохранения диалога ввода,
  владельца страницы, отозванного доступа, отсутствия повторных команд,
  пагинации камер и сцен, а также переходов между фото и текстовыми страницами.

- Фоновое обновление состояния отменяется при новом переходе или результате
  команды, даже если пользователь успел вернуться на тот же экран. Запоздавшая
  ошибка Telegram больше не удаляет актуальную сессию, а параллельные фоновые
  обновления не вытесняют загрузку выбранного пользователем экрана.
- В списке устройств группы сохраняются выбранный фильтр и страница после
  возврата через карточку группы. Восстановление не меняет состав группы и
  сохраняет проверку административных прав.
- Недостаток прав для административной кнопки теперь обозначен как отказ в
  доступе с возвратом в меню, а не как раздел «В разработке».
- Ручной ввод длительности графика сохраняет выбранное смещение даты, как
  кнопки готовых интервалов. Формат состояния диалога остался совместимым.

- Списки комнат и устройств разбиты на страницы по 10 элементов. Возврат из
  карточки сохраняет страницу отдельно для пользователя и раздела настроек.
  При изменении доступов или состава списка номер страницы ограничивается
  доступным диапазоном.
- Архив камер больше не ограничивает навигацию первыми 30 записями: доступны
  страницы по 10 записей. Фильтр и страница сохраняются при обновлении и возврате
  из записи; при каждом открытии повторно проверяется доступ к камере.
- Устройства, отсутствующие в ответе HA, остаются в комнате со статусом
  «Недоступно» и без быстрых команд. Сбой HA и пустые списки объясняются явно.
- Карточки показывают комнату из актуальной привязки в БД, пользовательское имя
  и `entity_id`. Одинаковые имена в списке различаются данными HA или устойчивым
  `entity_id`; расположение в подтверждении также берётся из БД.
- Климат показывает пределы и шаг температуры. Успешный service call подписан
  как отправка команды, отдельно от текущего состояния устройства.
- Графики сохраняют период при ошибке, повторном открытии и отмене ручного ввода.
  Пустая история показывает объяснение и сохраняет кнопки периода. Добавлены
  текущее состояние датчика и отдельное обновление выбранного периода.
- Время подготовки компактного меню снова видно и не меняется при повторе
  отправки после Telegram 429. В заголовках комнат убраны видимые звёздочки.
- Загрузка основных экранов выполняется с отменой устаревшего результата.
  Отмена во время замены фото текстом или наоборот удаляет только новое
  устаревшее сообщение, сохраняя действующий экран и контекст.
- Обновление сохранённого контекста с прежней командой устройства открывает
  состояние без повторного выполнения. Старые callback-индексы и поля диалогов
  сохранены; новые варианты навигации добавлены в конец перечислений.
- Добавлены регрессионные проверки страниц, фильтров, недоступности HA,
  отозванных прав, старых callback-байтов, отмены замены сообщения и переходов
  «фон камеры → график → снимок → длинный текст → фон камеры» на mock Telegram.

- Меню управления стали компактнее за счёт сокращения служебного текста и
  разделителей. Фоновое изображение, статус системы, графики, снимки и активные
  предупреждения сохраняются. После длинного текстового экрана фон возвращается
  при переходе к обычному меню.
- Кнопки комнат показывают действие или переход; одинаковые имена различаются
  уточнением из HA или entity_id. Заряд отображается как «Батарея · 97%», режимы
  климата локализованы, пользователям с правом просмотра доступны карточки состояния.
- Команды критичным устройствам и группам с такими устройствами требуют
  однократного подтверждения на 2 минуты. Подтверждается конкретная команда;
  права, ограничения температуры и состав группы проверяются перед отправкой.
  Отмена, обновление экрана и повторное нажатие не повторяют команду.
- Кнопки терморегулятора меняют уставку на шаг: быстрые нажатия выполняются
  по очереди с учётом задержки состояния HA. Повтор Telegram-обновления не
  повторяет команду устройству; устаревшая карточка не перекрывает навигацию.
- Кнопки света и выключателей передают конкретное включение/выключение,
  поэтому повторное нажатие прежней кнопки не отменяет первое действие.
- Для ручного интервала графика добавлена проверка диапазона 1–240 часов;
  некорректные callback-параметры отклоняются до запроса истории.
- Навигация графиков обрабатывается в фоне: новый выбор отменяет предыдущую
  загрузку, а выход с экрана отменяет ожидающее обновление. При ограничении
  Telegram обновление сообщения повторяется с учётом `retry_after`.
- Графики обновляются по кнопкам без фоновой перезагрузки изображения; убран
  повторный запрос состояния датчика, построение PNG вынесено из async-потока.
  Выбранный масштаб отмечен, кнопка «Текущее» сохраняет его.
- Графики датчиков показывают единицу измерения и обе даты периода; заряд
  батареи подписан явно. Убраны видимые символы разметки и ошибочная пометка
  «только что» у периода графика.
- Подключен экран климата с текущей температурой, уставкой и режимом. Кнопки
  учитывают уставку, шаг и границы устройства; просмотр и обновление пульта
  не отправляют команды. Режим с диапазоном температур доступен для просмотра.
- Пользователи с правом просмотра могут открывать графики датчиков и климат,
  сохраняя запрет на изменение устройств.
- После ошибки управления доступны обновление состояния, возврат и главное
  меню; обновление экрана не повторяет неудавшуюся команду.
- Исправлена ситуация, когда команда могла показать `Команда отправлена`,
  хотя Home Assistant вернул ошибку service call.
- Исправлена потеря pending-команды при ошибке выполнения после нажатия
  `Подтвердить`.
- Исправлен риск случайного архивирования устройств при частично упавшей
  синхронизации HA: архивирование пропускается, если хотя бы одна комната или
  entity не синхронизировались.
- Исправлен fallback после ошибки HA Conversation: локальный parser снова может
  выполнить поддерживаемые команды.
- Исправлена блокировка UI во время обработки voice-сообщения: распознавание
  выполняется в фоне.

### Security

- Уточнена документация по режиму `ha_conversation_full`: его следует выдавать
  только доверенным пользователям, потому что часть команд делегируется HA
  Conversation.

## [0.1.0] - 2026-06-02

### Added

- Персональные профили пользователей с ролями `user`, `child`, `guest`.
- Доступы к комнатам и устройствам: полный доступ, просмотр, скрыто.
- Персональный язык пользователя и базовая локализация интерфейса `ru/en`.
- Алиасы состояний и логическая инверсия отображаемых состояний устройств.
- Админский раздел камер с добавлением камер по комнатам.
- Снимки и короткие видео с камер через RTSP/HTTP без внешнего HTTPS-сервера.
- Работа с видео через `ffmpeg-next` и системные LibAV/FFmpeg библиотеки.
- Настраиваемые длительности коротких клипов камеры.
- Фон интерфейса из кадра выбранной камеры с настраиваемым интервалом обновления.
- Событийная запись камер по правилам Home Assistant.
- Архив записей внутри карточки конкретной камеры.
- Отправка одного сегмента или всех частей записи в Telegram.
- Сжатие видео перед отправкой в Telegram.
- Удаление временных файлов после отправки видео.
- Уведомления о готовой записи.
- Продление активной записи при повторном событии по той же камере.
- Нарезка длинной записи на сегменты с максимальной длительностью файла.
- Группы правил записи, включая базовые группы.
- Health-экран камер с последней проверкой, размером файла и ошибкой.
- Журнал активности для действий, камер, записей и ошибок.
- Текстовые команды для быстрых действий с устройствами и камерами.
- Защита от повторной отправки всех частей записи одной кнопкой.
- Индикатор активной записи в интерфейсе.

### Changed

- Камеры удалены из `options.json`: они создаются через Telegram-админку и
  хранятся в SQLite.
- Обновлена структура админки камер, правил, групп и health-экранов.
- Улучшена маршрутизация назад в админских экранах камер и правил.
- Улучшен поиск текстовых команд: учитываются alias, `entity_id`, комната и
  слова в любом порядке.
- Обновлен Dockerfile для runtime-библиотек FFmpeg/LibAV.
- CI и release validation теперь запускают `clippy -D warnings`.
- README полностью обновлен под текущее состояние проекта.

### Fixed

- Исправлены откаты UI-контекста при фоновых обновлениях и быстрых нажатиях.
- Исправлена блокировка UI при запросе видео с камеры.
- Исправлены проблемы пути возврата в меню камер и правил.
- Исправлена ошибка временного имени compressed MP4, из-за которой LibAV не мог
  определить формат output.
- Исправлено странное соотношение сторон отправляемого видео: видео
  масштабируется с сохранением исходной геометрии.
- Исправлено дублирование активных worker для одной камеры при нескольких
  подходящих событиях.

### Security

- README больше не содержит реальный пример Telegram user id в заголовке.
- В документации уточнено, что `.env`, `options.json`, SQLite-база и записи
  камер не должны попадать в репозиторий.
