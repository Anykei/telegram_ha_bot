# HTML-виджеты: дизайн «Дом» 1.1

Дата: 6 ноября 2026 года. Статус: развитие одобренного пилота. Правила 1.1 дополняют дизайн 1.0 навигацией и выбором вида; версия токенов остаётся `1.0.0`. Первый экран — один светильник с включением и выключением. Дальнейшие страницы описаны в [карте экранов](SCREENS.md). Доступ к реальному Home Assistant отсутствует и появится только после отдельного сообщения владельца. Внешний сайт, шрифты и изображения не используются.

## Характер интерфейса

Карточка должна быть похожа на домашний пульт: спокойная поверхность, читаемое состояние и одно основное действие. Зелёный акцент обозначает управление и включённое устройство. Декоративная иллюстрация светильника вторична; состояние всегда подписано словами. Время, мощность, яркость и прочие показатели появляются только при наличии фактических данных.

Основная последовательность: комната → имя устройства → подтверждённое состояние → действие → результат → обновление. Технический идентификатор находится под «Об устройстве». Демонстрационные настройки и отметка о симуляции относятся к оболочке предпросмотра, не к будущему рабочему пульту.

В навигационных экранах последовательность меняется на контекст → заголовок → короткое пояснение → список → возврат → обновление. Принцип остаётся общим: устройство, действие и его результат различимы без чтения служебных сведений. Демонстрационный бот помечает виртуальные устройства и сообщения как демо; внешняя оболочка preview не должна быть единственным местом, где это видно.

## Источник оформления

`ui/widgets/design-tokens.json` — основной источник значений. `src/tokens.css` соответствует ему: `shared` и `themes.light` задаются на `:root`, `themes.dark` — на `:root[data-theme="dark"]`. Runtime переключает атрибут `data-theme` корневого HTML-элемента по теме Telegram. Общие цвета поверхности, текста и подсказок наследуются из `--tg-theme-*`; резервные значения позволяют открыть локальный preview.

| Группа | Правило |
|---|---|
| Интервалы | Шкала 4, 8, 12, 16, 20, 24 px; внутреннее поле карточки 20 px, на узком экране 12 px |
| Типографика | Системный шрифт; имя 28 px, состояние 24 px, основной текст 15 px, подписи 12 px |
| Цвет | Светлая нейтральная поверхность / тёмная зелёно-серая; один зелёный акцент; красный только для ошибки |
| Геометрия | Скругление контролов и блока состояния 16 px, переключателя 99 px; радиус оболочки 24 px |
| Нажатия | Главный контрол не ниже 56 px, вторичные — 44 px |
| Движение | Смена положения переключателя 160 ms; при reduced motion переход отключён |

Комната и название занимают одну строку с многоточием при недостатке ширины; полное значение остаётся текстом элемента. Состояние может переноситься. Нельзя заменять текст состояния одним цветом, сжимать основные кнопки ради декоративного блока или показывать успешное выполнение до ответа бота. Карточка рассчитана на ширину 200–600 px; высота виджета ограничена Telegram, поэтому подтверждение заменяет основное действие. На ширине до 260 px кнопки подтверждения располагаются друг под другом.

## Компоненты и DOM

| Компонент | Контракт |
|---|---|
| `.card`, `#widget` | Контейнер; `data-state="off|on|offline|denied"` отражает подтверждённое состояние |
| `.kicker`, `#room` | Название комнаты и декоративная пиктограмма |
| `#name` | Пользовательское имя устройства; вставляется как текст |
| `.hero`, `#state` | Текущее состояние; `.lamp` — декоративная SVG-иллюстрация |
| `#power`, `#power-label` | Кнопка с текстом следующего действия и мини-переключателем текущего состояния |
| `#confirm-panel`, `#confirm-title`, `#confirm`, `#cancel` | Встроенное подтверждение критичного действия |
| `#status` | Результат или пояснение; доступен как live status в браузерном preview |
| `#refresh` | Запрашивает состояние, не повторяет управление |
| `#details`, `#device-id` | Сворачиваемая техническая информация |
| `.is-hidden`, `.is-disabled`, `.is-busy`, `.is-confirming` | Скрытый блок, запрещённое действие, ожидание, подтверждение; поведение блокируется также в JavaScript |

`#power` скрывается на время подтверждения, а `.is-confirming` на корневой карточке скрывает технические подробности, оставляя место для решения. `#confirm-panel` скрыт в остальных режимах. Модификатор `.is-disabled` отвечает за внешний вид; он не заменяет проверку прав и блокировку обработчика. Начальный HTML содержит только «Устройство» и «Нет данных». Имя и состояние поступают из модели, а не вшиваются как якобы актуальные значения.

## Состояния

| Ситуация | Что видит пользователь | Управление |
|---|---|---|
| Выключено | «Выключен», спокойная иллюстрация | «Включить свет» |
| Включено | «Включён», зелёный блок состояния, сдвинутый переключатель | «Выключить свет» |
| Запрос выполняется | Прежнее подтверждённое состояние и пояснение ожидания | Повторные запросы блокируются |
| Команда принята, состояние ещё не изменилось | Прежнее состояние; сообщение, что ожидается обновление | Не показывать подтверждение выполнения |
| Устройство недоступно | «Недоступен» и понятная причина | Управление закрыто; обновление доступно |
| Только просмотр | Актуальное состояние и «Только просмотр» | Основное действие закрыто |
| Доступ отозван | Обобщённое имя, отсутствие прежних данных и отказ в доступе | Управление закрыто |
| Нужно подтверждение | Конкретное действие и две кнопки | «Подтвердить» / «Отмена» |
| Ошибка / истёкшее подтверждение | Краткая причина; актуальное либо неизвестное состояние | Не повторять команду автоматически |

## Переиспользование

Следующие экраны используют тот же файл токенов и общие классы. Для климата заменяется содержимое `.hero` и главный контрол; для комнаты повторяются компактные строки устройств. У нового компонента должна быть одна основная задача, словесное состояние и отдельный результат запроса. Изменения токенов действуют на все экраны; исключения оформляются отдельным компонентом, без копирования полного stylesheet.

Управление сохраняет путь «виджет → Telegram → Rust-бот → Home Assistant». Права и подтверждения проверяет бот. В HTML и пересылаемое общее состояние не помещаются токены, адреса камер и персональные сведения о доме. Для приватных данных используется разрешённое состояние исходного чата после проверки доступа.

## Навигационные страницы 1.1

`ui/widgets/src/panel.html`, `panel.css` и `panel.js` — общий макет для демонстрационных экранов дома, комнат, комнаты, устройства и настроек. Они используют те же `--ha-*` токены. Отдельный panel сохраняет компактность первого switch-виджета и позволяет проверять перенос страниц по очереди.

| Компонент | Правило |
|---|---|
| Контекст и заголовок | Одна строка каждый; название комнаты или раздела, без длинной цепочки пути |
| Пояснение | Не более двух коротких строк; только сведения, необходимые для выбора |
| Блок состояния | Использовать для значения устройства; не показывать фиктивные метрики дома |
| Строка списка | Имя 14 px, дополнительная строка 11 px, высота не меньше 56 px; вся строка — один переход |
| Основное действие | Один зелёный элемент; его текст называет действие, например «Включить свет» |
| Выбранный вариант | Светлая акцентная поверхность, граница и знак ✓; цвет не является единственным признаком |
| Навигация | Отдельный ряд «Назад» / «Дом»; цели не меньше 44 px |
| Обновление | Отдельная кнопка после навигации; запрашивает данные текущей страницы |
| Сообщение результата | Короткая строка внизу, сохраняющая смысл при ширине 200 px |

На одной HTML-странице — до четырёх строк. Большие списки требуют страниц; вертикальная прокрутка внутри виджета не используется. В демонстрации одна комната и один прибор, поэтому пагинация не нужна. Количество строк обычного интерфейса сохраняется до отдельного изменения его пагинации.

В `panel` выбранный пункт обозначает текущий выбор, а не подтверждённое состояние лампы: последнее всегда выводится в блоке состояния. После нажатия интерфейс оставляет старое значение до ответа бота. При ошибке изменения блокируются до успешного обновления. Переходы между разделами остаются доступны, когда нет незавершённого запроса.

## Выбор вида интерфейса

Два варианта называются **«Обычный»** и **«HTML»**. Это способ отображения, а не светлая или тёмная тема. Выбор размещается в «Мои настройки» отдельной группой «Вид интерфейса» и отмечается знаком ✓. Пояснение к экспериментальному HTML сообщает фактический объём поддержки, например «Пробные экраны управления».

- Выбор относится к пользователю и не влияет на других участников.
- Переключение сохраняет текущий раздел и открывает его представление без повторного управления устройством.
- Если раздел пока не перенесён, он открывается обычным видом; сохранённое предпочтение HTML не сбрасывается. Короткая пометка объясняет причину.
- Если клиент не отображает виджет, должен оставаться обычный путь возврата: команда и/или кнопка вне HTML. Переключатель, доступный только внутри неподдерживаемого виджета, недостаточен.
- На переходе показано «Открываем выбранный вид…». Старые действия блокируются; новое сообщение принимает запросы после создания сервером.
- Смена вида не отменяет уже принятую физическую команду и не подтверждает её выполнение.

В демо выбор сравнивает два представления одной виртуальной модели. Сохранение предпочтения и поддержка реальных разделов основного бота — отдельные шаги интеграции.

## Проверка дизайна

- Светлая и тёмная темы; ширины 200, 340 и 600 px.
- Основное действие, ожидание, ошибка, только просмотр, отзыв доступа и подтверждение.
- Длинное имя устройства не перекрывает контролы; подписи читаются без внутренней прокрутки.
- Выключатель не меняет подтверждённое положение во время ожидания.
- Все действия доступны без наведения мыши; размер целей не меньше 44 px.
- Собранный HTML вместе с поведением укладывается в 32 КБ исходного текста и 4 КБ zlib.
- Дом, комнаты, устройство и настройки используют одинаковые размеры контролов и словарь действий в обоих видах.
- Переключение вида, возврат и обновление не меняют состояние устройства.
- Устаревшая карточка после переключения вида не принимает новые изменения.

Нативный Telegram может иначе отображать неподдерживаемые атрибуты доступности. Браузерный preview проверяет композицию и логику, но не подтверждает совместимость с каждым клиентом Telegram.

## Релизный компонент r1

`release.html/css/js` отображает данные штатных Rust-экранов. Внутри компонента
нет имён устройств, количества комнат или конкретных команд HA. Их задаёт
backend; служебные подписи имеют варианты RU/EN. Общие токены «Дом» сохранены.

Кнопки различают переход (`nav`), действие (`action`), подтверждение (`danger`)
и выбранное значение (`selected`). Семантику задаёт сервер по исходному Payload,
а не по тексту кнопки. Оптимистическое изменение состояния запрещено: после
подтверждения приёма запроса интерфейс ждёт новое состояние сообщения.

Серверные страницы ограничены 1000 байтами JSON и четырьмя рядами по две кнопки.
Текст, предупреждения и исходные кнопки не удаляются ради компактности. При
узкой ширине компонент показывает дополнительные локальные части; это не
отправляет запросы и не выполняет действие. Заголовок с многоточием повторяется
полностью в сведениях, если не помещается. Слишком большой неделимый элемент
предлагает открыть `/classic`.

Главная страница сохраняет избранное и все существующие разделы. Выбор вида
персональный; неподдержанная страница открывается обычным видом с сохранением
предпочтения HTML. Сетевые ошибки не приводят к автоматическому повтору команды.
Подробности интеграции и границы готовности описаны в [RELEASE.md](RELEASE.md).

### Типы рабочих экранов 1.2

Сервер передаёт `kind`: меню, список, устройство, климат, подтверждение или форма.
Текст состояния собран на отдельной поверхности; у устройства и климата он
крупнее. Подтверждение имеет акцент слева, а кнопка окончательного опасного
действия выделена цветом ошибки. Обычный переход к карточке остаётся нейтральным.
Тип экрана не вычисляется из пользовательского текста и не изменяет права.

Форма содержит подсказку `hint` с явным указанием ответить сообщением в этот чат.
Она показывается на первой серверной странице и целиком сохраняется при локальном
разбиении. Поля ввода внутри HTML не имитируются. Отмена использует исходный
серверный callback либо `/cancel`; обновление не создаёт новый черновик.

Длинный абзац делится только при необходимости; соседние части на одной локальной
странице объединяются, чтобы не создавать искусственные разрывы текста. Все
подписи добавляются через `textContent`. Проверены 184 сочетания на ширинах
200, 320, 360 и 430 px, включая RU/EN, светлую/тёмную темы и ошибку подтверждения.
