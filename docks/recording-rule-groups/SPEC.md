# Спека: группы правил записи

## Цель

Сделать группы правил понятным пользовательским инструментом, а не скрытой
технической настройкой.

Группа должна отвечать на два вопроса:

- из каких правил она состоит;
- включена она сейчас или стоит на паузе.

Типовые сценарии:

- `Охрана`: включить запись всех охранных событий;
- `Ночь`: включать ночные правила одной кнопкой;
- `Двери`: быстро поставить на паузу все правила по дверям;
- `Тест`: держать тестовые правила отдельно и выключенными в проде.

## Не Цель

- Не менять движок записи камер.
- Не удалять привязку групп из карточки правила.
- Не делать сложный редактор выражений для групп.
- Не вводить автоматическое включение/выключение групп по расписанию в MVP.
- Не делать разные группы для каждого пользователя в MVP.

## Текущее Состояние

Уже есть таблицы:

- `camera_recording_rule_groups`;
- `camera_recording_rule_group_items`.

Группа имеет:

- `id`;
- `name`;
- `enabled`;
- `created_at`;
- `updated_at`.

Связь правила с группой хранится отдельно:

```text
camera_recording_rule_group_items
group_id
rule_id
```

Matcher уже учитывает группы: правило не срабатывает, если хотя бы одна
назначенная ему группа выключена.

## Принятая Семантика MVP

В MVP группа - это глобальный переключатель-предохранитель для набора правил.

Правило работает так:

- если правило не входит ни в одну группу, оно работает как обычно;
- если правило входит в одну группу, оно работает только когда эта группа
  включена;
- если правило входит в несколько групп, оно работает только когда включены все
  его группы.

Иными словами, группы дают `all-of-groups` поведение.

Это важно явно показывать в UI:

```text
Правило работает, когда включены все выбранные группы.
Выключенная группа ставит связанные правила на паузу.
```

Почему так:

- это совпадает с текущим `camera_recording_matcher`;
- не нужна миграция БД;
- выключение группы никогда случайно не активирует правило через другую группу;
- группа `Тест` может безопасно держать тестовые правила на паузе.

## Будущая Семантика Режимов

Если понадобится логика "правило работает, когда включена любая из групп",
нужно не переопределять текущие группы молча, а добавить отдельную модель
режимов или политику активации.

Возможная будущая миграция:

```text
camera_recording_rule_groups.kind:
  guard      -- текущий предохранитель, all-of-groups
  mode       -- пользовательский режим, any-enabled
  label      -- организационная метка, не влияет на запуск

camera_recording_rules.group_activation_policy:
  all_enabled
  any_enabled
```

До такой миграции UI не должен обещать OR-семантику.

## Роли И Права

### Root/Admin

Root может:

- создавать группы;
- создавать базовые группы;
- переименовывать группы;
- удалять группы;
- включать и ставить группы на паузу;
- добавлять правила в группу;
- удалять правила из группы;
- видеть все группы и все правила.

### Обычный Пользователь

Обычный пользователь может видеть и включать группы только если это безопасно.

MVP-правило доступа:

- группа видна пользователю, если в ней есть хотя бы одно правило с камерой из
  комнаты, которую пользователь может видеть;
- группа доступна для переключения, только если все правила группы относятся к
  комнатам, где пользователь имеет право управления;
- если группа содержит правила из недоступных комнат, она показывается как
  read-only или не показывается вообще.

Безопасный вариант для первого релиза:

- управление составом групп только в админке;
- включение/пауза групп для обычных пользователей выключены до появления
  явного права доступа.

Следующий этап:

- добавить отдельное право `can_toggle_recording_groups`;
- показывать пользовательский экран "Режимы записи" только тем, кому это право
  выдано.

## Время Активности Правила

Группы решают ручную активацию набора правил, но правило также должно уметь
работать только в заданное время. Это отдельная настройка правила, а не группы.

Примеры:

- правило двери активно всегда;
- правило движения активно только ночью: `22:00-07:00`;
- правило температуры активно только днем: `08:00-20:00`;
- правило тестовой камеры активно только по будням.

### Семантика

Правило может иметь одно из состояний:

- `Всегда` - временного ограничения нет;
- `Ежедневно с HH:MM до HH:MM`;
- `По дням недели с HH:MM до HH:MM`.

Окно может пересекать полночь:

```text
22:00-07:00
```

означает: активно с 22:00 сегодня до 07:00 следующего дня.

Если день недели включен, а окно пересекает полночь, ночная часть после
полуночи относится к предыдущему активному дню. Например, `Пт 22:00-07:00`
активно с пятницы 22:00 до субботы 07:00.

Время считается в локальной таймзоне бота. В UI это нужно показывать явно:

```text
Время бота: Europe/Moscow
```

### UI В Карточке Правила

В карточке правила добавить строку:

```text
Активно: всегда
```

или:

```text
Активно: 22:00-07:00 · Пн-Пт · Europe/Moscow
```

Если правило сейчас вне активного окна:

```text
Сейчас правило на паузе по времени.
Ближайшая активация: сегодня 22:00.
```

### UI В Мастере Правила

В мастере создания правила шаг времени активности идет после срока хранения и
перед выбором групп:

```text

[Всегда]
[Ночь 22:00-07:00]
[День 08:00-20:00]
[Свое время]
```

Дефолт: `Всегда`.

Если пользователь пропускает шаг, правило создается без временного ограничения.

### Хранение В БД

Для реализации нужна миграция. Минимальная модель в `camera_recording_rules`:

```text
active_time_enabled INTEGER NOT NULL DEFAULT 0
active_from_minute INTEGER
active_to_minute INTEGER
active_days_mask INTEGER NOT NULL DEFAULT 127
active_timezone TEXT
```

Где:

- `active_time_enabled = 0` означает `Всегда`;
- `active_from_minute` и `active_to_minute` - минуты от начала дня: `0..1439`;
- `active_days_mask` - битовая маска дней недели, 7 бит;
- `active_timezone` пустой или `NULL` означает локальную таймзону бота.

Валидация:

- время должно быть в формате `HH:MM`;
- `HH` от `00` до `23`;
- `MM` от `00` до `59`;
- `from != to`, потому что круглосуточный режим задается как `Всегда`;
- пустая маска дней запрещена.

### Matcher

Проверка времени должна быть отдельным шагом до проверки условий события.

Если правило сейчас не активно по времени:

```text
rule skipped: inactive time window
```

Это не ошибка записи и не должно попадать пользователю как failed recording.
Для diagnostics достаточно debug/activity log.

### Взаимодействие С Группами

Формула активации правила:

```text
rule.enabled
AND all selected groups are enabled
AND current time is inside active window
AND event/conditions match
```

Группа не должна автоматически включаться или выключаться по времени в MVP.
Если нужно "ночное поведение", лучше сделать:

- группу `Ночь`;
- правила в этой группе;
- у самих правил окно `22:00-07:00`.

Автопереключение группы `Ночь` по расписанию - отдельный будущий stage.

Пользовательский экран нужен отдельно от админского CRUD.

Возможный путь:

```text
Камеры -> Режимы записи
```

или:

```text
Главное меню -> Режимы записи
```

Экран:

```text
Режимы записи

Включенная группа разрешает связанные правила.
Выключенная группа ставит их на паузу.

[✅ Охрана · 4 правила]
[⏸ Ночь · 2 правила]
[⏸ Тест · только просмотр]

```

Карточка режима:

```text

Статус: включена
Правил: 4

[Назад]
```

Правила безопасности:

- обычный пользователь не может создавать, переименовывать или удалять группы;
- обычный пользователь не может менять состав группы;
- обычный пользователь может только включать/ставить на паузу разрешенные
  группы;
- если группа затрагивает недоступные комнаты, переключатель скрыт или экран
  показывает "нет прав на управление всей группой".

## Влияние На Запись

При каждом событии HA matcher проверяет правило.

Порядок проверок:

1. правило не удалено;
2. правило включено;
3. все группы правила включены;
4. текущее время попадает в окно активности правила;
5. source/conditions соответствуют событию и текущему состоянию;
6. cooldown позволяет старт записи;
7. worker запускает запись.

Если группа выключена:

```text
rule skipped: group paused
```

Это не ошибка записи и не должно попадать пользователю как failed recording.
Для diagnostics достаточно debug/activity log.

## Activity Log

Все ручные действия с группами должны попадать в журнал:

- `rule_group.create`;
- `rule_group.rename`;
- `rule_group.delete`;
- `rule_group.enable`;
- `rule_group.pause`;
- `rule_group.add_rule`;
- `rule_group.remove_rule`;
- `rule_group.create_defaults`.

Изменение времени активности правила логируется отдельно:

- `recording_rule.active_time_update`;
- `recording_rule.active_time_reset`.

Поля:

- `user_id`;
- `kind = recording`;
- `entity_type = rule_group`;
- `entity_id = group_id`;
- `action`;
- `status`;
- короткое сообщение без секретов.

## Empty И Edge Cases

### Нет Групп

Показывать:

```text
Групп пока нет.
Создайте свою группу или нажмите "Создать базовые".
```

### Группа Без Правил

Карточка группы должна показывать:

```text
Правил: 0
Группа пока ни на что не влияет.
```

### Правило В Выключенной Группе

В карточке правила показывать:

```text
Группы: Охрана, Тест ⏸
Сейчас правило на паузе из-за выключенной группы: Тест.
```

### Удаление Последней Группы Правила

Если у правила больше нет групп, оно работает по обычной логике `enabled` +
conditions.

UI должен показать:

```text
Группы: не выбраны
```

### Повторное Нажатие Старой Кнопки

Если пользователь нажал старую кнопку из уже открытого Telegram-экрана:

- роутер не должен падать;
- если группа уже удалена, показать список групп и alert "Группа не найдена";
- если payload старого toggle, выполнить toggle или открыть карточку группы.

## План Реализации

### Stage 1: Админское Управление Группами

- список групп с кнопками `Создать группу` и `Создать базовые`;
- карточка группы;
- rename/delete/toggle;
- тексты RU/EN;
- router payload test для всех новых callback.

### Stage 2: Состав Группы Из Карточки Группы

- экран `Правила в группе`;
- список правил с группировкой по комнатам;
- multi-select;
- фильтр `все / выбранные / не выбранные`;
- пагинация;
- activity log для add/remove.

### Stage 3: Улучшение Карточки Правила

- показывать выключенные группы с `⏸`;
- показывать причину, почему правило сейчас на паузе;
- добавить `Создать группу` на экран выбора групп правила;
- явно объяснить `all-of-groups` семантику.

### Stage 4: Время Активности Правила

- миграция для полей `active_time_*`;
- formatter текущего окна активности;
- редактор `Всегда / Ночь / День / Свое время / Дни недели`;
- проверка времени в matcher;
- отображение причины паузы в карточке правила;
- тесты для обычного окна, окна через полночь и дней недели.

### Stage 5: Пользовательская Активация

- экран `Режимы записи`;
- видимость групп по доступным комнатам;
- запрет toggle, если группа затрагивает комнаты без права управления;
- activity log для enable/pause от пользователя.

### Stage 6: Будущие Режимы

Только если понадобится OR-семантика:

- миграция `kind` или `activation_policy`;
- UI выбора типа группы;
- matcher tests для `all_enabled` и `any_enabled`.

## Acceptance Criteria

- Админ может создать группу с коротким названием.
- Админ может создать базовые группы без дублей.
- Админ может открыть карточку группы из списка.
- Админ может переименовать группу.
- Админ может удалить группу, не удаляя правила записи.
- Админ может добавить правило в группу из карточки правила.
- Админ может добавить правило в группу из карточки группы.
- Выключенная группа останавливает связанные правила.
- Включенная группа снова разрешает связанные правила.
- Правило без групп работает как раньше.
- Правило с `Активно: всегда` работает как раньше.
- Правило с окном `22:00-07:00` работает внутри окна и пропускается вне окна.
- Окно активности через полночь считается корректно.
- UI явно показывает, что правило работает только когда включены все выбранные
  группы.
- Старые открытые Telegram-кнопки не ломают роутер.
- Все callback payload проходят проверку размера Telegram.

## Тесты

Минимальный набор:

- DB: `create_group` не создает пустое название.
- DB: `create_group` идемпотентен по имени.
- DB: `rename_group` не позволяет дубли.
- DB: `delete_group` удаляет связи и не удаляет правила.
- Matcher: правило без групп работает.
- Matcher: правило в выключенной группе не работает.
- Matcher: правило в двух группах работает только когда обе включены.
- Matcher: правило вне окна активности не работает.
- Matcher: правило в окне активности работает.
- Matcher: окно активности через полночь работает.
- Router: все group payload roundtrip и меньше лимита Telegram callback.
- Access: обычный пользователь не может переключить группу с недоступными
  комнатами.
- UI: пустой список групп показывает `Создать группу` и `Создать базовые`.
